04 / Arquitectura viable

Primero un flujo vertical de descubrimiento.

01 · Entrada

Raíces UNC autorizadas, lista maestra, propietario y permisos.

02 · Worker

Python aprobado, os.scandir, identidad solo lectura, límites SMB, ledger y reanudación.

03 · Catálogo

SQLite/FTS5 privado, versión, estado, evidencia, búsqueda y exportación controlada.

04 · Validación

Tika/POI o Docling, OCR selectivo, reglas con página/sección; revisión humana.
Después de la autorización: API con SSO/RBAC y RAG con permisos efectivos, citas, revocación y pruebas de aislamiento. No introducir grafo, agentes autónomos ni minería sin necesidad demostrada.

Java permanece para reglas y servicios existentes; Python se propone para automatización, extracción y análisis si el estándar corporativo lo permite. No se verificó ese estándar interno.

11 / Decisión para dirección

Autorizar un piloto reversible, no una transformación abierta.

  • Confirmar responsable, universo SGCI, permisos, entorno privado y estándar técnico.
  • Acordar capacidad y traspaso de tickets; escoger escenario mínimo o preferido y reestimar presupuesto.
  • Autorizar dos semanas de descubrimiento/benchmark y revisar resultados antes de ampliar.
  • Capacitar con Claude Academy y laboratorios propios; insignia no equivale a certificación profesional. No comprometer exámenes ni partnership.
  • Posponer RAG productivo, PWA, Element externo, agentes autónomos y compra masiva hasta superar gates.
Mensaje ejecutivo: el objetivo no es introducir IA por sí misma, sino identificar reglas, controles y oportunidades de mejora, con menor retrabajo y trazabilidad demostrable.
